# SceneForge 项目计划书

> 版本：v0.1（实施基线）  
> 状态：已确认方案，进入第一阶段实施  
> 项目定位：将单张或多张风景照片重建为可追溯、可编辑、可分级发布的高精度 3D 场景工程。

## 1. 项目目标

SceneForge 面向整个风景场景，而非只重建单个物体。系统根据用户提供的照片、地名和可选位置信息，拆解地形、建筑、植被、水面、天空与光照，生成统一的场景母版，并派生适合不同设备的 3D 版本。

项目坚持以下结果可交付：

1. **整个场景可重建**：近景、中景、远景与动态效果分层处理。
2. **高精度母版可编辑**：保留米制尺寸、独立元素、材质、来源和参数，不把场景焊成不可拆分的大网格。
3. **补全过程可追溯**：明确区分照片事实、地理数据、参考资料和生成式推断。
4. **按需降级**：所有发布档从同一母版派生，不因降级破坏高精度源资产。
5. **后续工作基于同一工程**：调整布局、颜色、模型和画质均通过 `scene.json` 与生成脚本完成，可验证、可回滚。

## 2. 非目标与能力边界

- 不承诺单张照片完成测绘级或照片级的真实还原。
- 不把单图深度估计当作真实尺寸；未提供尺度时使用类别先验并显式标注。
- 不让通用 AI 3D 服务一次性生成整幅风景；AI 3D 主要用于近景独立物体。
- 不把摄影测量产生的原始高面数网格直接视为可编辑工程模型。
- 不把树叶、水面、玻璃、天空等不稳定对象强行转换为静态高精度网格。
- 无法确认地点时，只声明“风格近似场景”，不伪造真实地理位置。
- 不使用来源和授权不明的网络图片作为场景贴图。

## 3. 核心原则

数据可信度按以下顺序选择：

> 真实地理数据 > 多图几何重建 > 单图与资料联合重建 > 类别先验 > 生成式猜测

同时遵循：

- **语义分层**：建筑、地形、植被、水面和天空独立建模与验收。
- **来源优先**：每项关键资产记录 `source`、`confidence` 和 `assumptions`。
- **先勘察后生成**：照片覆盖不足或地点未确认时，先反馈补拍/确认，不直接输出看似完整的结果。
- **母版与发布物分离**：高精度资产不可被网页降级流程覆盖。
- **局部修改不破坏已确认区域**：通过版本、区域锁和渲染对比控制回归。

## 4. 场景分层与技术路线

| 层级 | 内容 | 首选方式 | 单图降级方式 |
| --- | --- | --- | --- |
| 近景 | 亭、桥、房屋、台阶、岸边 | COLMAP/OpenMVS + Blender 清理 | AI 3D 单物体 + Blender 修整 |
| 中景 | 岸线、道路、树林、建筑群 | OSM/地形数据 + 参数化生成 | 图像布局 + 类别参数化 |
| 远景 | 山体、城市轮廓、地平线 | DEM/公开地理数据 | 单图深度和轮廓约束的参数化山体 |
| 动态层 | 水面、云、风摆、落叶 | three.js 程序效果 | 同左 |
| 光照层 | 太阳、天空、雾、阴影 | 时间/地点/照片联合估计 | 照片光照估计，标注假设 |

最终采用混合场景：适合几何重建的部分保留网格，适合程序生成的部分保留生成器和参数。

## 5. 总体流水线

```text
单图 / 多图 / 地名 / EXIF 位置
              ↓
       输入检查与场景勘察
              ↓
 地点确认、外部数据检索、照片覆盖评估
              ↓
     元素拆解与用户重建意图确认
              ↓
 近景重建 / 地形生成 / 植被与动态层生成
              ↓
       Blender 高精度场景母版
              ↓
 灰模布局 → 重点区域 → 材质 → 原图对照验收
              ↓
 自动 LOD、压缩、three.js 发布与版本管理
```

## 6. 输入模式

### 6.1 多图模式

- 独立物体推荐 12~20 张，独立建筑 20~40 张，小场景 30~60 张。
- 相邻照片保持约 60%~80% 重叠，覆盖平视、较高机位与关键细节。
- 预审检查模糊、曝光、覆盖方向、重叠、动态物体和反光风险。
- 覆盖不足时给出具体补拍方向，不直接承诺完整重建。

### 6.2 单图且地点可确认

- 地点来源包括用户地名、EXIF GPS 或明确地标，并经用户确认。
- 可检索 OSM、公开 DEM、开放卫星影像与授权明确的参考资料。
- 岸线、道路和地势优先使用地理数据；建筑背面按资料和结构规则补全。

### 6.3 单图且地点不可确认

- 按可识别的场景类型和元素类别重建。
- 采用通用尺寸、结构、植被和地貌先验。
- 所有推断均标记为假设，交付物声明为风格近似场景。

## 7. 场景数据契约

`scene.json` 是场景工程的唯一真源，JSON Schema 为第一项正式编码交付。

Schema 至少覆盖：

- 工程元信息、Schema 版本、场景 ID、重建意图和单位坐标系。
- 输入照片及其哈希、EXIF 摘要、授权与隐私处理状态。
- 地点识别结果、用户确认状态、地理数据来源和许可。
- 相机、地形、光照、天气与动态效果。
- 元素 ID、类型、空间层级、变换、尺寸、生成器/资产引用。
- 材质、纹理、色彩来源和反照率估计说明。
- 每项来源、置信度、假设、人工确认和区域锁。
- 高精度母版与 LOD 派生物、压缩和发布配置。
- 勘察、灰模、重点区域、原图对照、降级等验收状态。
- 工程版本和回滚关系。

报告和生成器只允许通过场景 ID、元素 ID 和资产 URI 引用工程内容，避免复制出多份互相矛盾的数据。

## 8. 勘察报告

每次重建先生成勘察报告，至少包括：

1. 输入清单、照片质量与隐私检查。
2. 地点识别、证据、置信度和用户确认。
3. 重建意图：真实地点优先、照片构图优先或风格参考。
4. 场景元素拆解与空间层级。
5. 每张照片/外部数据的用途与覆盖范围。
6. 多图角度覆盖、缺失方向和补拍建议。
7. 单图不可见区域、遮挡和结构补全假设。
8. 外部服务、数据许可、素材授权和上传提示。
9. 推荐重建路线、重点区域与验收门槛。
10. 阻塞项和需要用户做出的最少决策。

报告同时提供人读 Markdown 与机读结构化数据；二者由同一份勘察结果生成，禁止手工维护两份不同结论。

## 9. 高精度母版与降级

母版保留：

- 米制坐标、独立语义元素和可编辑几何。
- 原始/高分辨率纹理、UV、材质和光照。
- 相机、地形、植被、水面参数。
- 来源、假设、置信度、版本和区域锁。

派生发布档：

| 档位 | 用途 | 主要处理 |
| --- | --- | --- |
| master | 编辑与归档 | 不作为网页默认下载 |
| lod0 | 高端桌面 | 轻微减面，保留高分辨率纹理 |
| lod1 | 普通桌面 | 减面、2K 纹理、完整动态效果可选 |
| lod2 | 网页默认 | 更远距离简化、1K 纹理、植被实例化 |
| lod3 | 移动/低性能 | 低面数、512 纹理、降低植被密度与动态效果 |

统一使用 Blender 减面/清理、植被实例化、KTX2 纹理、Meshopt 或 Draco 几何压缩。降级报告记录面数、纹理体积、下载量与视觉效果变化。

## 10. 用户反馈与验收关卡

1. **勘察确认**：地点、元素、外部服务、隐私和重建意图。
2. **拆解确认**：来源、置信度、假设、补全策略。
3. **灰模布局**：比例、朝向、岸线、相机和元素关系。
4. **重点区域**：用户指定高精度区域与可简化区域。
5. **原图对照**：按形、位、色、缺四类反馈，每轮最多选 1~3 个优先项。
6. **降级验收**：确定网页默认档、移动档和动态效果开关。

反馈界面或报告必须明确下一步需要用户做什么，不用技术参数代替决策。

## 11. 技术架构

计划采用单仓库组织：

- `schemas/`：JSON Schema、示例和兼容策略。
- `templates/`：勘察报告与验收报告模板。
- `pipeline/`：Python 勘察、图像处理、地理数据、COLMAP/OpenMVS、Blender 编排。
- `generators/`：地形、植被、建筑等参数化生成器。
- `viewer/`：three.js 预览、元素选择、原图对照和 LOD 调试。
- `web/`：后续上传、确认、任务和版本管理模块。
- `tests/`：Schema、单元、流水线契约与渲染回归测试。

外部能力均通过适配器接入：视觉模型、AI 3D、OSM/DEM/卫星数据。核心场景数据不绑定某一家供应商。

## 12. 隐私、安全与许可

- 默认本地处理照片、几何重建、Blender 和 LOD。
- 上传照片到外部视觉/AI 3D 服务前必须获得当次明确授权。
- EXIF GPS 默认不进入公开日志；公开仓库和报告不得包含用户私人照片或密钥。
- API key 只从环境变量或本地未提交配置读取。
- 外部数据记录来源、许可、获取日期和缓存约束。
- 网络图片不得直接作为贴图，除非许可证和再分发权明确。
- 街景和地图服务不作为默认数据源，接入前单独审查条款。

## 13. 实施阶段

### 阶段 1：工程契约与勘察基线

- 项目计划书。
- `scene.json` JSON Schema 与最小完整示例。
- Schema 校验和负向测试。
- 勘察报告 Markdown 模板与结构化字段约定。

### 阶段 2：混合场景最小闭环

- 照片/地名输入、勘察结果生成。
- 地形、建筑、植被、水面和动态层装配。
- three.js 灰模与场景预览。
- 原图对照和版本化。

### 阶段 3：多图几何重建

- 照片覆盖预审。
- COLMAP/OpenMVS 流水线。
- Blender 清理、比例校准和资产入库。

### 阶段 4：单图与知识补全

- 地点识别、地理数据检索和参考资料溯源。
- AI 3D 单物体适配器。
- 假设、置信度和补全区域可视化。

### 阶段 5：高精度母版与自动 LOD

- 母版资产管理、减面、纹理和几何压缩。
- 各档预览与降级报告。
- 区域流式加载和性能预算。

### 阶段 6：Web 子模块

- 上传、勘察确认、元素拆解、区域验收、画质切换和版本管理。

## 14. 第一阶段验收标准

- Schema 使用公开 JSON Schema 标准，版本固定，字段有明确含义。
- 能表达单图、多图、真实地点、未知地点和混合来源场景。
- 能表达高精度母版、LOD、假设、置信度、用户确认和区域锁。
- 最小完整示例通过校验；缺关键字段、非法置信度、错误 URI/枚举等负向用例被拒绝。
- 勘察报告模板覆盖第 8 节全部内容，并明确阻塞项和用户动作。
- 不引入外部照片、密钥或供应商锁定。

## 15. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 整场景比例和布局失真 | 先灰模验收，米制尺度与地理约束优先 |
| 单图补全被误认为事实 | 来源/置信度强制字段，低置信度高亮 |
| 高精度模型不可编辑或过大 | 语义分层、母版与发布物分离、自动 LOD |
| 多图覆盖不足导致破洞 | 前置覆盖预审和具体补拍指导 |
| 外部 AI 结果不稳定 | 适配器隔离、版本化、人工关卡与回滚 |
| 地理数据与照片年代/季节冲突 | 允许照片构图优先，记录冲突并由用户选择 |
| 隐私和素材授权问题 | 默认本地、上传前授权、来源许可审计 |

## 16. 开发约定

- 文档和代码注释使用中文；标识符使用英文。
- 所有生成资产必须可追溯到输入、脚本、参数和版本。
- 不手写 GLB 二进制；模型通过 Blender 或明确受支持的重建工具生成。
- 修改 Schema 必须保留版本迁移说明，并同步示例、校验和报告模板。
- 每次功能改动执行对应自动化测试；视觉改动必须附原图/基线渲染对比。
- 用户确认前不覆盖已验收母版；发布档只从母版派生。
