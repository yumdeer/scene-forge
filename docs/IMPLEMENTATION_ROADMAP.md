# SceneForge 实施路线

> 版本：v0.2（2026-11 更新专项 P1 进度）
> 上位文档：[项目计划书](PROJECT_PLAN.md)
> 技术依据：[技术方案](TECHNICAL_DESIGN.md)、[开源项目适配对比](OPEN_SOURCE_COMPARISON.md)

## 1. 路线总览

实施遵循“契约先行、体量优先、能力分段接入”的原则。每个阶段结束必须通过该阶段门禁，才进入下一阶段。

| 阶段 | 目标 | 主要交付 | 出口门禁 |
| --- | --- | --- | --- |
| 0 | 工程准备 | 仓库结构、环境清单、依赖版本锁定策略 | 环境可重复安装 |
| 1 | 契约与勘察 | `scene.json` / `survey.json` Schema、示例、报告模板、校验测试 | Schema 正负向测试通过 |
| 2 | 单图最小闭环 | 单图理解、参数化建筑 Builder、灰模预览、主视图对照 | 单图建筑主视图轮廓通过 |
| 3 | 多图几何 | COLMAP 管线、相机求解、实体关联、尺度对齐 | 多图相机与比例稳定 |
| 4 | 道具与自然 | 单物体资产适配器、Infinigen/Geometry Nodes 植被地形 | 道具与植被可编辑、可实例化 |
| 5 | 母版与 LOD | 母版管理、减面压缩、发布档、降级报告 | 四档 LOD 结构不破坏 |
| 6 | Web 子模块 | 上传、确认、任务、版本管理 | 端到端流程可用 |
| 专项 | 复杂地标（布达拉宫） | 分步白模、分区、立面、材质与对照报告 | 主视图高一致验收 |

阶段 6 为可选范围；阶段 1~5 是发布前必须完成的核心链路。

## 2. 阶段 0：工程准备

### 交付

- 仓库目录：`schemas/`、`pipeline/`、`generators/`、`templates/`、`tests/`、`docs/`。
- 依赖清单：Blender 版本、Python 版本、COLMAP 版本、分割/深度模型版本与权重来源。
- 外部服务清单：模型服务、数据服务、各自的许可与调用边界。
- 本地缓存与临时目录约定（照片、mask、点云、重建结果）。

### 门禁

- 新机器按文档可完成环境安装；
- 依赖版本全部固定，不使用浮动 latest；
- 不在仓库中出现密钥、照片或未授权资产。

## 3. 阶段 1：工程契约与勘察基线

### 交付

1. `scene.json` Schema（已有初稿）与最小完整示例；
2. `survey.json` Schema 与勘察报告模板；
3. Schema 校验工具与负向测试集；
4. 勘察输出与人读报告的生成关系（同一数据源，禁止手工双维护）；
5. `scene.json` v1.1 提案：`observations`、`relations`、`fidelity`、`geometryConstraints`、`cameras[].solvedFrom`。

### 门禁

- 最小示例通过校验；
- 缺关键字段、非法置信度、错误枚举、错误 URI 等负向用例全部被拒绝；
- 报告模板覆盖计划书第 8 节全部内容；
- 契约能表达单图/多图、已知/未知地点、推断与人工确认。

## 4. 阶段 2：单图最小闭环

目标：先证明“单图 → 可编辑建筑 → 主视图对齐”这条链路成立，不追求多图。

### 交付

1. 单图勘察：质量检查、元素拆解、尺度假设、重建意图确认；
2. 视觉证据：Grounding DINO + SAM 2 + Depth Anything V2 的观测输出；
3. 建筑 Builder v1：体量、墙体、屋顶、窗阵列、墙带；
4. Blender headless 执行器：确定性构建、失败诊断、对象命名规范；
5. three.js 或 Blender 灰模预览：主视图、三分之四、低机位；
6. 主视图对照报告：轮廓 IoU、关键分界线、高度比例。

### 门禁

- 灰模（无细节）主视图轮廓对齐后才允许生成立面细节；
- 相同 `scene.json` 重复构建结果一致；
- 元素可单独选中与修改，导出优化版不覆盖母版结构；
- 失败信息能定位到元素与阶段。

## 5. 阶段 3：多图几何重建

### 交付

1. 照片覆盖预审：方位扇区、重叠、基线、缺失方向与补拍指令；
2. COLMAP 适配器：相机、稀疏点云、可选稠密重建；
3. 跨图实体关联：稀疏点反投影 + 标签/实例投票 + 几何一致性检查；
4. 尺度对齐：控制点/实测/地理数据，写入 `dimensions.estimated`；
5. 相机驱动的参考渲染与主视图校验。

### 门禁

- 多图相机求解可重复；
- 实体合并不使用外观相似度单独判定；
- 覆盖不足时明确降级，不输出“完整重建”假象；
- 尺度来源可追溯。

## 6. 阶段 4：道具与自然场景

### 交付

1. 单物体资产适配器：TRELLIS 为首选，TripoSR 为基线，Hunyuan3D 仅作 PBR 对照；
2. 产品 Builder：参数化主体 + 生成网格部件的混合结构；
3. 植被 Builder：单株参数化与 Infinigen 封装；
4. 群落散布：Geometry Nodes 按密度、坡度、水线与道路避让；
5. 地形 Builder：地理数据优先，无数据时高度场 + 轮廓约束。

### 门禁

- 生成资产完成命名、缩放归一与材质对齐后才进入场景；
- 道具与植被均可通过参数调整，而非整体网格变形；
- 散布不穿过道路、水面与建筑；
- LOD 前母版分布不被破坏。

## 7. 阶段 5：母版与自动 LOD

### 交付

1. 母版资产管理：`master.blend`、`master.glb`、材质与相机；
2. 减面、纹理压缩（KTX2/WebP）、几何压缩（Meshopt/Draco）；
3. `lod0~lod3` 发布档与降级报告；
4. 区域流式加载与性能预算；
5. 版本与回滚机制。

### 门禁

- 各档位从母版派生，不反向修改母版；
- 降级后主体结构、主要颜色分区不破坏；
- 报告记录面数、纹理体积、下载量与视觉差异；
- 已锁定区域在重建中保持不变。

## 8. 阶段 6（可选）：Web 子模块

- 上传与隐私授权；
- 勘察结果确认（地点、元素、服务、尺度）；
- 任务状态与失败重试；
- 区域验收与版本对比。

门禁：从上传到发布档生成可端到端跑通，且每步都有用户明确确认点。

## 9. 专项里程碑：布达拉宫

作为复杂地标的验收样例，独立于阶段顺序，可在阶段 2 后启动。

### 9.1 输入

- 主参考图（正立面）；
- 可选的侧面、背面、屋顶、局部细节图；
- 已知尺度或带焦距的 EXIF；
- 用户确认的验收口径：主视图高一致。

### 9.2 分解步骤

| 步骤 | 内容 | 门禁 |
| --- | --- | --- |
| P1 | 山体、台基、白宫、红宫、东西翼、屋顶群的体量划分 | 主视图轮廓与分区对齐 |

P1 进度（2026-11）：实体与相机已落契约，覆盖门禁 15/15，主视图配准 2/2 通过（`building_main` IoU 0.81、`red_palace` 0.90）；正视图 0/2，卡在东侧墙脚随地形下探（高度 +12.2%）与红宫宽度跨视角冲突（−13.7%）。细节见[技术方案 8.2](TECHNICAL_DESIGN.md)与[专项复盘第 6 节](POTALA_CASE_STUDY.md)。
| P2 | 纯白模（无窗、无贴图） | 三分之四与低机位无纸片感 |
| P3 | 红白分区与边玛带 | 颜色分区位置与参考一致 |
| P4 | 窗阵列、屋顶群、角楼 | 窗距/窗高按区域独立，屋顶高差可控 |
| P5 | 材质、地形、光照、植被 | 原图对照四项（形/位/色/缺）处理完毕 |

### 9.3 明确禁止

- 用整体拉伸补偿宽高比；
- 用统一窗阵列铺满全楼；
- 用贴片面板表示窗户并当作最终构件；
- 导出前按材质合并导致部件不可编辑；
- 把单图推断的背面结构标为事实。

### 9.4 交付

- `master.blend`（保留语义对象树）；
- 主视图/三分之四/低机位/屋顶特写预览；
- 轮廓对齐与分区对照报告；
- `scene.json` 中完整记录假设与置信度。

## 10. 测试策略

| 层级 | 内容 | 工具 |
| --- | --- | --- |
| 契约测试 | Schema 正向/负向、版本迁移 | JSON Schema 校验器 |
| 单元测试 | 几何参数、Builder 计算、命名规则 | pytest |
| 契约集成 | 输入 → `scene.json` → Builder 调用 | 固定样例场景 |
| 渲染回归 | 固定机位渲染与基线差异 | Blender headless |
| 端到端 | 上传、勘察、构建、验收、导出 | 集成环境 |

要求：

- 视觉改动必须附原图/基线渲染对比；
- 每个阶段的门禁都要有可执行脚本，不靠人工口头确认；
- 失败用例进入回归集，不允许只修当次问题。

## 11. 依赖与风险

| 依赖 | 风险 | 缓解 |
| --- | --- | --- |
| 云端视觉模型 | 结果漂移、隐私、费用 | 固定版本、结果缓存、上传授权 |
| COLMAP/OpenMVS | 环境复杂、许可差异 | 容器化固定版本，许可单独评审 |
| Blender 版本 | API 变动 | 锁定版本，升级前跑渲染回归 |
| 模型权重许可 | 合规 | 默认链路只放许可清晰资产 |
| 复杂地标 | 人工确认成本高 | 体量优先、分步门禁、减少返工 |

## 12. 发布前总检查

- [ ] 契约测试、单元测试、渲染回归全部通过；
- [ ] 阶段 1~5 门禁全部有可执行证据；
- [ ] 每个交付场景包含 `scene.json`、母版、LOD、预览与报告；
- [ ] 未观测结构全部标记为推断；
- [ ] 第三方资产与数据许可记录完整；
- [ ] 布达拉宫专项通过主视图高一致验收。
