# 布达拉宫建模复盘

> 版本：v0.2（2026-11 补充 P1 实施记录）
> 对象：`yumdeer.github.io/tools/blender/potala.py` 中的既有布达拉宫模型
> 关联：[技术方案](TECHNICAL_DESIGN.md) 第 7.4 节、[实施路线](IMPLEMENTATION_ROADMAP.md) 第 9 节

## 1. 现状判断

既有模型不是“从照片自动重建”的结果，而是**人工按参考照片逐项调参的固定几何**：

- 白宫体块、红宫位置、东翼坡顶、金顶坐标全部是写死的数值；
- 注释中大量“之前做成…导致…现在改成…”的记录，说明模型是靠截图反复补救；
- 导出前用全局系数把建筑整体拉宽，以匹配照片的宽高比；
- 导出前按材质合并对象，牺牲了部件级可编辑性。

已经做对的部分（应保留并产品化）：

- 边玛墙用四道薄墙而不是一整块板，避免从上方看成棕色屋顶；
- 金顶拆为主金/高光金/暗金三档，靠明暗线读出体量；
- 相邻体块避免严格共面，减少远景 z-fighting；
- 金顶改为缓坡“平顶歇山”，不再做成尖锥。

问题在于这些修正停留在**单张照片的视觉补丁**层面，没有回到体量与相机的求解。

## 2. 失真原因

### 2.1 用整体拉伸补偿比例

脚本设置 `XS = 2.75`，在导出前把所有顶点的 X 坐标乘 2.75，依据是“实景正面宽高比约 3.6:1，而模型只有 1.3:1”。

后果：

- 正面宽度凑对了，但**进深、前后关系、侧视比例**没有对应求解；
- 三分之四视角会显得又宽又薄，像舞台布景；
- 小面板（窗套、窗洞）单独处理“只移位不拉伸”，导致同一立面里窗户与墙体的尺度关系不一致；
- 窗数需要按同一系数加密，本质是在补偿一个本不该引入的错误。

**正确做法**：先由相机、已知高度（台基/层高/门窗）与轮廓约束求解体量，再建模；不允许在导出阶段整体拉伸。

### 2.2 体量深度靠猜

白宫各块的前后位置（`yf`/`yb`）、红宫前脸退后量、东翼坡顶起止高度均为手工给定。单张正立面照片无法唯一确定这些量，因此：

- 正面可能勉强相似；
- 侧面像一排等高盒子；
- 红宫与白宫的搭接、屋顶群的纵深关系容易错；
- 山体与建筑结合处缺少真实退台。

**正确做法**：把不可观测量显式写成 `assumptions`，并用多图/地理数据/实测尺寸逐步收敛，而不是靠“看着差不多”。

### 2.3 窗户是贴片，不是构件

`win()` 用两块面板（白色窗套 + 深色窗洞）贴在墙面上。

后果：

- 近看或斜看时窗户像印上去的方点；
- 没有窗洞深度、窗框厚度与窗台投影；
- 立面阴影层次不足，远看容易变成网格纸。

**正确做法**：窗洞、窗框、窗棂、窗台分层建模，重复阵列用实例或 Geometry Nodes；允许按楼层/立面使用不同参数。

### 2.4 全楼共用一套重复规则

红宫用 9 排、步距 1.10 的窗阵列；东翼用 12 列（乘以 XS）沿斜檐排布；白宫各块窗排起始高度虽有微调，但仍是同一套逻辑。

后果：

- 真实建筑中“某段密、某段疏、某段不开窗”的节奏被平均化；
- 重复外观在远景中形成明显的机械感；
- 细节越多，错误的体量越被放大。

**正确做法**：先按区域划分立面（红宫正面、红宫侧墙、白宫各段、东翼坡顶、雪城），每个区域独立定义窗距、窗高、排数与起始高度。

### 2.5 金顶与屋顶群参数化过度统一

金顶由同一个采样函数生成，红宫顶一排 7 座，中心距 2.2、宽度 2.10~2.28，高度仅差 0.2 左右。

后果：

- 屋顶群看起来是复制品；
- 屋脊、戗脊、檐口的关系被统一规则压平；
- 远景只剩一条金色屋檐线，缺少真实的高低错落。

**正确做法**：屋顶类型、檐口标高、屋脊长度、起翘量、宝顶尺寸分别参数化；可见坡面先建，背面坡面标为推断。

### 2.6 导出前按材质合并

`merge_by_material` 把不同部件合成少数对象。

后果：

- 无法单独选中“某一面墙”“某一排窗”“某一座金顶”；
- 后续修改只能改 UV/材质，不能改结构；
- 与“可编辑优先”的目标直接冲突。

**正确做法**：母版保留完整对象树；仅导出优化版做合并，且不得回写母版。

### 2.7 先细节后体量

脚本里大量篇幅用于窗套宽度、金色分档、斜梯连续带、店铺灯箱等细节，而体量参数始终是手工常数。

后果：

- 体量错位时，增加细节只会让“错误建筑”更精致；
- 每次调整都在补丁上打补丁，难以收敛。

**正确做法**：设置硬门禁——灰模主视图轮廓未通过，不允许进入细节阶段。

## 3. 新流程

```text
主参考图（+ 可选侧/背/顶/细节图 + 尺度/EXIF）
        ↓
相机与尺度求解、主要轮廓与分界线提取
        ↓
体量划分：山体 / 台基 / 白宫 / 红宫 / 东翼 / 屋顶群
        ↓
P2 纯白模（无窗、无贴图） → 主视图 + 三分之四 + 低机位检查
        ↓
P3 红白分区、边玛带、台基斜线
        ↓
P4 窗阵列（按区域独立参数）、角楼、屋顶群
        ↓
P5 材质、地形、光照、植被 → 原图对照（形/位/色/缺）
```

## 4. 验收指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 主视图轮廓 IoU | ≥ 0.85 | 人工确认后可放宽，仅用于定位 |
| 关键分界线偏差 | 可量化、逐项记录 | 红白分区、台基顶线、东翼斜檐口 |
| 主要高度比例误差 | ≤ 3% | 红宫/白宫/台基相对高度 |
| 三分之四视角 | 无纸片感、无悬空体块 | 人工确认 |
| 色彩分区 | 位置与参考一致 | 不要求逐像素一致 |
| 可编辑性 | 墙体/窗/屋顶/台基可独立选中 | 母版对象树 |

## 5. 可复用结论

1. 复杂地标必须分步验收，体量优先。
2. 禁止导出阶段整体拉伸补偿比例。
3. 重复构件要参数化，但参数必须按区域独立。
4. 窗户、墙带、屋顶要建造成构件，不做平面贴片。
5. 母版与导出优化版分离，保护后续编辑。
6. 单图不可见结构一律标为推断，并在报告中单独列出。
7. 既有脚本中的防共面、边玛墙薄墙、金顶分档等经验继续保留，但抽成参数化模板，不再复制坐标。

### 6.3 当前门禁与未解问题

- 主视图 2/2 通过：`building_main` IoU 0.81、`red_palace` IoU 0.90；
- 正视图 0/2 通过：`front_building` 高度 +12.2%、`front_red_palace` 宽度 −13.7% / IoU 0.55。

两个未解问题：

1. **东侧墙脚随地形下探**：模型白墙东段底部随山体降到约 −32m，照片中白墙下沿近似水平，导致正视投影可见高度虚增。应从地形与墙脚建模口径解决，不能靠放大照片包围盒掩盖。
2. **红宫宽度两视角方向相反**：正视图要求约 71~72m，主视图在 62m 时已 +5.9%。说明红宫进深与前脸退后量也参与宽度投影，必须先独立量测主视图红宫，再做联合约束，禁止单向加宽。

### 6.4 流程教训

- **量测误差会被误读成“数据自相矛盾”**：同一形体在两视角给出相反的尺寸结论时，先复核量测本身，再怀疑照片或几何。
- **相机必须有自由度上限**：不限制俯仰/横移时，求解器会用相机去吸收体量错误（例如把主相机解到地下 z≈−22m）。
- **绝对尺度不能由配准反推**：配准只证明“在给定相机族内能否对齐”，均匀缩放对成像不可观测，米制尺寸必须来自外部尺度锚。
